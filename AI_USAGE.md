# AI Usage

## Что делалось с AI

AI использовал как ускоритель на рутине и объёме — не как замену себе.

- каркас: Vite, React, TypeScript, зависимости, базовая FSD-структура
- MSW: seed-данные, фильтрация, пагинация, логика мутации ставки
- UI-kit и страницы: список, деталка, ставки, форма ставки
- unit/RTL-тесты, README, a11y и адаптив

Сверял результат с OpenAPI, прогонял сценарии в браузере и правил то, что вышло криво или слишком шаблонно.

## Что решал сам

- Проверял функционал руками, писал и гонял тесты, добавлял то, чего не хватало по ТЗ и для нормального ревью (ESLint, Prettier, a11y, адаптив).
- Zustand вместо MobX. Для одного UI-флага (мобильные фильтры) MobX избыточен — Zustand проще и этого достаточно.
- Фильтры в URL, не в localStorage. Ссылку можно скинуть, состояние переживает рефреш; для фильтров списка localStorage хуже по UX.
- Типы из OpenAPI написал руками. С генерацией по схеме уже работал, но здесь что-то не взлетело — проще и надёжнее оказалось вручную.
- MSW-store обновляет состояние после POST ставки. Без этого моки были бы статичными заглушками — а ТЗ требует реальные mutations.
- Свой лёгкий UI-kit на Tailwind. Shadcn/Radix в задании не обязательны (есть в вакансии), поэтому так быстрее и без лишнего шума.
- Prefetch детали по hover/focus — улучшение UX; с реальным API имеет смысл отдельно посмотреть под нагрузкой.

## Что от AI отклонил

- тащить openapi-typescript несмотря на peer dependency conflict
- поднимать MobX на всё приложение, хотя клиентского state почти нет
- складывать фильтры в localStorage вместо search params
- собирать страницы одним большим компонентом без FSD-слоёв
- оставлять вложенные `<Link><Button>` — плохо для a11y, переделал на стилизованный `Link`

## Что проверял особенно внимательно

- совпадение с OpenAPI: request/response, enum’ы, nullable, формат 422
- мутация ставки в MSW: обновление list/detail/bets после успеха
- Zod для search params: битые значения не роняют страницу, есть fallback
- валидация ставки: min/max/step на клиенте и в моке
- edge cases из ТЗ: `hide_bets_history`, скрытые адреса/контакты, `no_view_cargo_price`, `can_set_bet=false`
- суффикс `*.component.tsx` для React-компонентов, как просили в задании

## Риски, которые остались

- в UI не выведены все поля схемы — только то, что нужно для сценариев задания
- сравнение step через float с допуском: на экзотических дробных шагах возможны краевые кейсы
- нет e2e (Playwright) — основные сценарии проверял руками + unit/RTL
- MSW-store живёт в памяти вкладки и сбрасывается после reload
